## 视觉方案

候选 A 选择“履带底盘 + 四角辅助支腿”作为可视化分支，座椅配俯仰转轴、执行器、扶手、右侧身体支撑和脚托，左侧设置摇杆、急停与显示占位。电池外壳位于低处。支腿的橙色部位便于观察动作。

画面采用浅色摄影棚背景、金属机架、深色座垫和橡胶履带，前左方视角展示左手控制器与履带。座椅保持空置；没有制作实际用户的身体、面部或动作形象。效果图的封面和短片使用同一场景，首段保留相同外观，后续仅改变相机、部件姿态及场景。

这是外观讨论方案，并非结构架构选型结论。四角支腿、铰点、伸缩长度、内部锁止、安装截面和完整运动包络均未确定。模型中的尺寸由绘图程序直接定义，不由 `config/layout-study.json` 的质量/重心模型推导，不能把本图、计算示例或视频合并为已经闭合的工程设计。

## 动作分镜

| 时间 | 内容 | 表达的意图 |
|---|---|---|
| 0–3.5 s | 整机外观 | 先理解整体结构和控制器位置 |
| 3.5–8.5 s | 底盘倾斜、座椅反向转动 | 理想化俯仰调平；不是调平控制仿真 |
| 8.5–12 s | 接近单级高差 | 展示 400 mm 目标及接近方向 |
| 12–16 s | 展开支腿 | 前方支撑伸向顶面，后方支撑留在下层 |
| 16–20 s | 抬升底盘 | 支腿辅助抬升，座椅保持水平的构想 |
| 20–26 s | 向顶面转移 | 履带向前转移、后支腿抬起并转移 |
| 26–30 s | 落稳、收回支腿 | 顶面落地后收回机构的意图 |
| 30–34 s | 完成画面与后续工作提示 | 保留未完成接触、载荷及故障保持验证的说明 |

动作采用人工关键帧，并按画面轨迹调整支腿线段长度；没有固定连杆闭合、执行器行程、速度或力矩约束。接触点并非由碰撞/接触求解器生成，不能用于判断运动是否能实现、是否会打滑、是否稳定或是否能够失电保持。画面出现的完整越障动作不表示 400 mm 通过能力已经实现。下降、连续楼梯及实际乘员工况均未在本片建模。

## 重新渲染

依赖：Python 3.10+、Chrome 或 Edge。导出视频还需要可用的 `ffmpeg`，或已安装且含二进制的 `imageio_ffmpeg`；分镜拼图需要 Pillow。

```powershell
# 首次下载锁定的 three@0.180.0，然后输出效果图和分镜
python visualization/render.py

# 同时输出视频：34 秒、1280 × 720、20 fps、H.264，无音轨
python visualization/render.py --video
```

可通过 `--output` 指定不同版本目录，避免覆盖需要保留的版本；通过 `--fps`、`--width`、`--height` 设置视频规格。效果图和分镜始终以 1920 × 1080 渲染。画面布局按 16:9 制作。

依赖下载自固定版本 npm 包，只读取 `three.module.js`、`three.core.js` 及 MIT 许可证，不执行包安装脚本。三维文件和许可证存入被忽略的 `visualization/vendor/`。本地 HTTP 和 DevTools 接口仅用于渲染期间的本机访问，任务结束后浏览器和服务退出。

若需要交互预览，先运行一次渲染器以取得依赖，再启动：

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory visualization
```

在浏览器打开 `http://127.0.0.1:8000/`，空格播放/暂停，R 重播。浏览器预览与导出视频调用相同的逐帧函数。
